# memo-ja — 素の思考メモ体

計画メモ・TODO・思考の下書きなど「他人に見せる前提のない素の思考ダンプ」を書く。
以下の <style_profile> を厳密に守って文章を生成する。<example> は参考文体サンプル
であり、内容ではなく文のリズム・語尾・構造だけを模倣する。

適用対象: ユーザー本人だけが読む日本語の作業文書 (scratch-docs、next-session
プロンプト、観測メモ、計画メモ、TODO リスト)。人に見せる文書 (PR 本文、レポート、
記事) には適用しない — そちらは humanize-ja / natural-japanese の領域。

<style_profile>
- 主語（一人称含む）は書かない。動作主を明示せず、非人称的な動詞終わりか体言止めで
  文を終える。「〜が削減される」「〜になる」のように受動・自動詞で結ぶか、名詞句の
  まま止める。「私は」「〜と考える」のような主語つき一人称構文は使わない。
- 数値・因果関係・効果・優劣を主張する文にのみ、直後か次の短文で自己への疑いを
  一言添える。文末は次のいずれかで締める:「〜と考えられる」「〜と言える」
  「〜だろうか」「〜か」「ほんとか」「一応根拠ほしいかも？」「概算である」
  「推測である」。単なる方針記述や事実描写の文には無理に付けない。
- 見出しは体言止め・名詞句のみで統一する（「目的」「概要」「特長/限界」「課題」の
  ように）。2章以上、または2ケース以上を扱う文書では、同一のラベルセットを全章で
  使い回す。見出しに動詞や敬体は混ぜない。
- 太字・記号装飾（**、絵文字、囲み枠、記号による強調）を使わない。強調したい箇所も
  普通の地の文か通常の箇条書きで書く。
- 断定的な主張の直後に、根拠が薄いことを示す短いメタ注釈を必ず付ける。文書調では
  「なお、〜は推測であり、〜はあくまで概算である。」の形。メモ調では文末に短い
  自己ツッコミを添える（「要確認」「根拠ほしい」「TODO:」を文末に置いてよい）。
- 同じ言い回し・同じ指摘は、章やケースをまたいでも推敲せずそのまま繰り返す
  （言い換えない）。意図的に誤字を作らない。自然に生じた表現のゆらぎだけ許容する。
- 接続語（そして、しかし、また、なお、したがって等）は最小限にとどめる。特に
  見直し・圧縮する場面では接続語を削って名詞句や体言止めの連続に圧縮する。
  初稿相当の丁寧な地の文を書いた後、削るなら「〜すること」「〜の点」のような
  名詞句化で短くする。
- 多重従属節（「〜し、〜することで、〜になる」のような連鎖）は説明的な計画パート
  でのみ使い、TODO・メモ的な箇所では使わない。
- 自分向けの作業指示や注意は、本文中に括弧書き（「※〜」「（〜）」）でそのまま
  混在させてよい。清書して別セクションに切り出さない。
- 全体として「他人に見せる前提のない下書き」のトーンを保つ。丁寧語（です・ます）は
  基本使わず、である体・体言止め・名詞句を基調にする。
</style_profile>

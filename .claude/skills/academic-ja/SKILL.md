# academic-ja — 論文・レポート体

瀬戸翔一氏の文体を模倣して、フォーマルな学術・技術文書 (卒業論文、修士論文、
学会発表原稿、技術レポート) を執筆する。以下の <style_profile> に列挙したルールを
すべて適用する。曖昧な「硬めに」「丁寧に」といった解釈ではなく、下記の具体的な
語尾・構成・語彙のセットに厳密に従うことが最優先。

このスキルの出力を humanize-ja / natural-japanese に通さない。この文体が義務化する
パターン (各節冒頭のメタ宣言文、全段落の三段構成、体言止め見出し) は、あちらの
lint・文体憲法がまさに検出・排除する対象であり、通すと文体が壊れる。

<style_profile>
- 文の長さ: 1文は40〜90字を目安とし、「Aである。しかしBのため、Cとなる」のように
  根拠節1つ＋帰結節1つの二段構成を基本形とする。3段以上に伸ばすのは論理的に必要な
  場合に限り、1段落内で3文以上連続して同一の二段構成を繰り返さない。
- 段落構成: 必ず「①背景・現状の提示 → ②課題／制約の指摘（『しかしながら』
  『〜が、』で受ける） → ③『そこで』『したがって』で結論・方針を述べる」の
  三段構成にする。結論なしで段落を終えない。
- 主語: 一人称（私・筆者・we）は日本語本文で使用禁止。主語は「本研究では」
  「本設計では」「本節では」「本テーマでは」のいずれかを立てる。
- 見出し: 動詞・助詞で終わる見出しを禁止し、必ず体言止め・名詞句にする
  （例:「〜の検討」「〜系」「〜の現状」「結論と展望」）。
- 強調表現: 太字・イタリック・下線・絵文字を地の文で使用禁止。強調したい箇所は
  副詞「特に」「実際」のいずれかを使うか、箇条書きまたは図表参照に切り出す。
- 具体性: 数値・企業名・製品名・規格名は単位付きで具体的に列挙し、初出には出典を
  個別に付す。抽象的な一般論だけで終わらせない。
- 文末表現: 段落・文の締めは次のいずれかに限定する。
  - 推定・見込み: 「〜と考えられる」「〜と見込まれる」「〜と言える」
  - 決定・方針: 「〜こととする」「〜を検討する」「〜を行う」
  - 必要性: 「〜必要がある」「〜が求められる」
- 節・章の冒頭: 各section/subsectionの最初の文は「本節では〜について述べる」
  「本節では〜について検討する」というメタ宣言文で始める。
- 専門用語の初出: 英語正式名称と略称が公式に定義されている用語（規格名・API名・
  プロトコル名等）にのみ「日本語名称＋英語正式名称（略称）」の三点セットを適用する
  （例:「ソフトウェア定義無線(Software Defined Radio, SDR)」）。英語名が存在しない、
  または広く定着していない語は日本語表記のみで導入する（不自然な直訳を作らない）。
- 見出し階層: section→subsection→subsubsectionと最低3段まで細分化し、末端見出しは
  対象名のみの極短名詞句にする（例:「構造部材」「フレーム形状」）。
- 推敲ルール（下書きを渡された場合、または自分で初稿を書いた後に必ず以下を適用して
  圧縮すること）:
  1. 「まず〜。その上で〜。その後、〜。」のように複数の独立文で時系列の完了動作を
     並べている場合、「〜し、〜し、〜した。」という連用中止の1文につなぎ直す。
  2. 名詞の前に2つ以上の修飾要素（節または句）が連続してかかっている場合は、
     意味的に必須な1つだけを残し他を削るか、別の文に分割する。
  3. 暫定性を示す語（「今回は」「一旦」）は最終稿では基本的に外し、「本研究では」を
     主語にした確定的な言い切りに置き換える。ただし「制約により今回は〜とする」
     という譲歩構文がどうしても必要な場面でのみ例外的に残してよい。
</style_profile>

# 実行時の指示

1. 与えられたトピック・データについて、上記<style_profile>のすべてのルールに
   従って文章を生成する。
2. 見出しは体言止めで、section→subsection→subsubsectionの階層を作る。
3. 各subsectionの冒頭は「本節では〜について述べる」で始める。
4. 段落は背景→課題→そこで／したがって、の三段構成を守る。
5. 文末は指定した文末表現セットのみを使い、断定は避けつつ方針は明示する。
6. 数値・固有名詞は具体的に、単位・出典付きで書く。
7. 初稿を書き終えたら、必ず推敲ルール1〜3を自己チェックとして適用し、時系列の
   独立文を連用中止でつなぎ直し、二重修飾を削り、暫定語を確定的な言い回しに
   置き換えてから最終稿として提出する。

# 参考規範 (裏取り)

規則セットは本人の実文から抽出したものであり改変しない。以下は各規則が一般的な
作文規範と整合することの確認:

- である体・体言止め見出しは日本語論文の標準 ([科学技術論文の書き方](http://okada-lab.org/Ronbun/JSyntax/KihonNoBuntai.php) ほか大学執筆ガイド)。
- 章冒頭のメタ宣言文・構成予告は読み手の認知負荷を下げる標準作法 ([中央大学ライティング・ラボ](https://www.chuo-u.ac.jp/uploads/2025/04/campuslife_learning_space_writinglab_01.pdf) 等)。
- 連用中止は書き言葉的で技術文書に適する。ただし一文が伸びるため使いすぎに注意 — 本プロファイルの40〜90字上限がそのガードを兼ねる ([MIT 書き言葉](https://web.mit.edu/kakikotoba/renyoo-chuushi.html) ほか)。
- 推敲ルール2 (二重修飾の削減) は本多勝一『日本語の作文技術』の修飾語原則 (節を先に・長い修飾語を前に) と同じ問題への対処 ([要約](https://www.math.nagoya-u.ac.jp/~shinichiroh/2018/02/13/japanese-punctuation.html))。
- 「と考えられる」には責任所在が曖昧という批判もある ([日本語で論文を書こうとする人へ](http://isabelle.cc.kyushu-u.ac.jp/~amano/how_to_write/japanese.html)) が、本プロファイルは文末セットを推定・決定・必要性に区分し、ヘッジを推定にのみ許すことで既にこの批判に対処している。
